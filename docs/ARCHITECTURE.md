# Architecture

Status: accepted 2026-11-12. Scope: `aphrody-labs/msys`, a source/metadata distribution for Windows modelled on Arch Linux (pacman, PKGBUILD, ABS, devtools, archiso), tuned like CachyOS (ISA repos, clang, LTO/PGO/AutoFDO, one settings package), with MSYS2 patches (msys2-runtime, path conversion, environments), and two-way bridges to the Windows-native ecosystem (winget + DSC v3, PowerShell 7/PSGallery, NuGet/.NET, vcpkg, MSIX, Win11 SDK). The repo holds recipes, metadata, configs and generators; binaries are built elsewhere (fr2/CI), never on the owner PC.

Hard rules:
- No duplication of `$SRC_ROOT` (`../src`): anything already in `src/third_party` is referenced through `pins.toml`; src wins on conflict (ADR 0005).
- Every name and location comes from `identity.toml` (ADR 0008, rule from `labs/docs/ROOT-ARCHITECTURE.md`): tools read `tools/lib/identity.ts`; no absolute paths, no hard-coded product name.
- WSL/WSL kernel/WSLg are reference architecture only; nothing here installs or runs WSL (ADR 0007).
- Tooling is bun only (`tools/*.ts`); `just` recipes are the entry points.
- `tools/check-structure.ts` enforces the tree below: an undocumented directory or file fails the check.

## Layers

Lower layers never depend on higher ones. A file may reference same-layer or lower-layer paths only (docs/graph/site/ci/tools are layer 8 and may read anything).

| # | layer | dirs | depends on | role |
|---|---|---|---|---|
| 0 | identity + pins | `identity.toml`, `pins.toml` | none | names, relocatable roots, external references |
| 1 | toolchains | `toolchains/` | 0 | LLVM (clang/clang-cl/lld/lld-link), MSVC STL + SDK, GNU, zig cc, Rust, .NET |
| 2 | runtimes / CRTs | `runtimes/` | 0-1 | UCRT, msvcrt, cygwin, libc++/libstdc++/MSVC STL, msys2-runtime |
| 3 | environments | `environments/` | 0-2 | MSYS, UCRT64, CLANG64, CLANGARM64, MINGW64, msvc-x64/arm64, linux-x64 reference |
| 4 | build system | `buildsys/` | 0-3 | makepkg profiles per env x ISA, clean-chroot contract, PKGBUILD conventions |
| 5 | repos | `repos/` | 0-4 | Arch-style pkgbase tree: core / extra / mingw (+ binary ISA variants) |
| 6 | formats + compat | `formats/`, `compat/` | 0-5 | pacman db, vcpkg, winget, NuGet, PSGallery, MSIX, xmap; POSIX and Windows surfaces |
| 7 | distribution | `distribution/` | 0-6 | keyring, mirrors, settings package, images/installers |
| 8 | meta | `docs/`, `graph/`, `site/`, `ci/`, `tools/` | all | design, generated views, CI, scripts |

## Build and data flow

```
third_party PKGBUILDs --pkgbuild-graph.ts--> graph/ + repos/*/meta.json + docs/MATRIX-PACKAGES.md
$SRC_ROOT/third_party/vcpkg/ports --vcpkg-map.ts--> formats/vcpkg/mapping.json
graph + vcpkg map + $SRC_ROOT/third_party/winget-pkgs + nuget.org + PSGallery --xmap.ts--> formats/xmap/
docs + graph + formats --site.ts--> site/dist/
fr2/CI: repos + buildsys (env x ISA) --clean chroot--> .pkg.tar.zst --sign (keyring)--> R2 mirrors --images--> installer / MSIX / winget
```

## Package model

- Primary format: pacman (`.pkg.tar.zst`, pkgbase/split packages, repo db, signatures). Everything else is a projection (ADR 0002, 0006).
- Repos: `aphrody-core` (closure of `base`), `aphrody-extra`, `aphrody-mingw`; binary ISA variants `-v3`, `-v4`, `-znver4` share recipes, differ only by `buildsys/makepkg` profile (CachyOS model, ADR 0004). No multilib: i686/mingw32 is dropped; arm64 is a separate env (CLANGARM64, msvc-arm64), not a multilib repo.
- Environments: CLANG64 is primary (LLVM, UCRT, libc++); msvc-x64 is the Windows-native ABI for vcpkg/NuGet/MSIX consumers; MSYS is the POSIX tool env (msys2-runtime); UCRT64 parity; MINGW64 upstream-only (ADR 0003).
- Kernel-manager philosophy (CachyOS) maps to "runtime manager": choosing msys2-runtime / CRT variants is a pacman-level choice, never a manual DLL swap.

## Two-way compatibility

| direction | surface | mechanism | boundary |
|---|---|---|---|
| POSIX -> Windows | bash/sh, coreutils, pacman, FHS | MSYS env (msys2-runtime) for tools; native envs for libraries | POSIX emulation never leaks into native env DLLs |
| POSIX -> Windows | path semantics | msys2-runtime argv/env conversion + `MSYS2_ARG_CONV_EXCL` | only at MSYS -> native process exec |
| POSIX -> Windows | gcc/glibc semantics | gcc in UCRT64; glibc only in linux-x64 reference (fr2) | no glibc emulation on Windows |
| Windows -> POSIX | winget | xmap inbound ids; outbound manifest for the installer | winget installs the distro, pacman installs packages inside it |
| Windows -> POSIX | DSC v3 | configuration documents that install the distro + envs | declarative machine state only |
| Windows -> POSIX | PowerShell 7 | PSGallery module wrapping env/pacman | pwsh never required by tools |
| Windows -> POSIX | NuGet / .NET | native libs packed per RID; NativeAOT built with msvc env | NuGet is a projection, not a second source |
| Windows -> POSIX | vcpkg | overlay triplets (labs) + mingw-llvm triplet; xmap port ids; binary caching on R2 | ports stay upstream in src |
| Windows -> POSIX | MSIX | launcher/installer with execution aliases | no packages shipped as MSIX individually |
| reference only | WSL / WSL kernel / WSLg | ideas: init/launcher split, per-distro rootfs, GPU/compositor bridging, DrvFs path model | never installed or executed |

## Identity and naming

- `identity.toml` holds name, title, org, git remote, package/winget/NuGet/PSGallery prefixes, site port, sibling roots. Renaming = edit identity.toml + regenerate (`just graph xmap site`) + `just check`.
- Tools resolve `ROOT` from their own location and `SRC`/`LABS` from identity.toml or `SRC_ROOT`/`LABS_ROOT`; no `C:\` paths in tracked tools.
- Own pacman packages: `<pkg_prefix>-*`; winget ids `<winget_publisher>.*`; NuGet `<nuget_prefix>.*`; modules `<psgallery_prefix>.*`.

## Cross-ecosystem map

`formats/xmap/XMAP.md` (top 300 by reverse-dependency count from `graph/graph.json`, msys and mingw pkgbases merged by real name). Columns: pacman pkgbase, repo, vcpkg port, winget id, NuGet id, PSGallery module. Heuristic matches carry `*`; curated values in `formats/xmap/overrides.toml` win.
